# 产品与技术决策日志

> 版本：V0.1  
> 规则：已确认项可直接指导开发；建议默认项在没有相反决定时使用；待确认项不得被实现为不可逆结构。

## 1. 已确认决策

### D-001 基础项目

- 决策：使用 `yf-team/yf-boot-exam` 作为二开底座。
- 状态：已确认。
- 影响：保留 Java/Spring Boot、Vue 3/TypeScript、MySQL、Redis、Quartz 技术栈。

### D-002 Git 仓库关系

- 决策：代码已导入用户自己的 GitHub 仓库，不保留对原仓库的 Git remote 依赖。
- 状态：已完成。
- 备注：原始导入基线 tag 为 `baseline-yf-boot-exam`。

### D-003 开发方式

- 决策：当前仅一名开发者，项目跑通阶段可以直接在 `main` 开发，后续稳定后再使用功能分支。
- 状态：已确认。
- 约束：仍需小提交和可运行检查点，不能将多个无关功能堆在一个提交中。

### D-004 岗位维护

- 决策：岗位是公司相对固定的基础数据，由系统管理员预先维护。
- 状态：已确认。
- 影响：HR 不创建岗位。

### D-005 HR 职责

- 决策：HR 录入/导入候选人、选择固定岗位、发放已有考核、查看结果。
- 状态：已确认。
- 影响：HR 不创建题库、组卷规则或考核模板。

### D-006 候选人入口

- 决策：候选人不注册，通过固定候选人入口输入姓名和考核码。
- 状态：已确认。
- 影响：所有候选人可以使用同一个入口 URL，每人考核码不同。

### D-007 员工账号

- 决策：保留员工正式账号和注册功能，用于入职、晋升和日常考核。
- 状态：已确认。
- 影响：注册页面改为员工注册；候选人页面不提供注册。

### D-008 核心身份

- 决策：系统管理员、HR、员工、候选人是核心身份；出题/阅卷人员可以作为可选角色。
- 状态：已确认。

### D-009 部署方向

- 决策：最终支持公司内网/私有部署，数据保存在公司控制环境。
- 状态：已确认。

### D-010 固定考核场景

- 日期：2026-09-03（替代 2026-09-02 的旧场景定义）。
- 决策：V1 固定三种场景：`INTERVIEW`（面试）、`REGULARIZATION`（转正）、`PROMOTION`（晋升）。
- 状态：已确认。
- 影响：候选人发放自动匹配 `INTERVIEW` 模板；旧 `ENTRY` 数据迁移为 `INTERVIEW`，旧 `GENERAL` 数据迁移为 `REGULARIZATION`。
- 依据：业务方确认选题顺序为“部门 → 岗位 → 面试/转正/晋升”。

### D-019 部门岗位职级结构与题库分类

- 日期：2026-09-03。
- 决策：岗位为可复用基础数据，与部门多对多关联；岗位下可维护多级职级，晋升目标职级允许暂时为空。
- 决策：题库业务分类固定为“入职招聘”和“员工晋升”，选题定位仍按部门、岗位、应用场景和可选目标职级完成。
- 状态：已确认并实现 V006、V007 Flyway 迁移及管理页面。

### D-020 初始组织结构

- 日期：2026-09-03。
- 决策：公司根节点显示为“全品轩”，可选直属部门只保留“餐具部”和“家具部”。
- 状态：已确认并通过 V008 Flyway 迁移实现。
- 影响：原演示部门技术部、财务部、商务部改为停用并从组织树隐藏，底层记录保留用于兼容历史账号和业务数据。
- 约束：“全品轩”为公司根节点，仅用于展示组织层级，不允许作为题库、岗位、模板或候选人的业务部门；业务部门只能选择其下的餐具部或家具部。

### D-011 员工考核发放权限

- 日期：2026-09-02。
- 决策：V1 由系统管理员或 HR 给员工分配考核，不设置部门负责人发放角色。
- 状态：已确认。

### D-012 考核码长度

- 日期：2026-09-02。
- 决策：候选人考核码固定为 6 位大写字母和数字，排除易混淆字符。
- 状态：已确认。

### D-013 候选人录入字段

- 日期：2026-09-02。
- 决策：候选人姓名、候选人编号、手机号、邮箱、岗位、招聘批次、开始时间和截止时间均由 HR 录入，作为 V1 必填业务字段。
- 状态：已确认。
- 边界：不建设简历管理，不采集完整简历或身份证号。

### D-014 Excel 导入策略

- 日期：2026-09-02。
- 决策：正确行正常导入，错误行不落库并返回逐行错误报告。
- 状态：已确认。

### D-015 员工注册审核

- 日期：2026-09-02。
- 决策：员工可以自由注册，注册后由系统管理员或 HR 审核。
- 状态：已确认。

### D-016 考生结果展示

- 日期：2026-09-02。
- 决策：候选人和员工最终只展示是否通过，不展示客观分、主观分、总分、标准答案或解析。
- 状态：已确认。
- 影响：管理员、HR 和授权阅卷人仍可按权限查看完整成绩和阅卷信息。

### D-017 禁止重考

- 日期：2026-09-02。
- 决策：同一考核分配不允许重考，每条分配在整个生命周期内只关联一份试卷。
- 状态：已确认。
- 影响：未交卷时重复进入恢复同一份试卷；交卷、过期或停用后不能生成新试卷。确需再次考核时，由系统管理员或 HR 新建考核分配。

### D-018 考核码默认有效期

- 日期：2026-09-02。
- 决策：候选人考核默认有效期为 14 天，从可进入时间开始计算。
- 状态：已确认。
- 影响：表单默认带出截止时间为开始时间加 14 天；结合 D-013，HR 可在发放前按实际安排调整开始时间和截止时间。

### D-019 员工联系方式

- 日期：2026-09-02。
- 决策：员工注册时手机号和邮箱均不必填。
- 状态：已确认。
- 影响：姓名、账号、密码、工号、部门和验证码仍为 V1 必填项；工号作为正式员工唯一业务标识。

### D-020 结果公布时机

- 日期：2026-09-02。
- 决策：考核结果自动公布，不需要 HR 手工发布。
- 状态：已确认。
- 影响：纯客观题在交卷结算后自动公布；含简答题的考核在最终阅卷完成后自动公布。考生仍只看到是否通过。

### D-021 HR 人员管理查询权限

- 日期：2026-09-03。
- 决策：HR 获得部门树和角色列表的只读查询权限，用于人员管理页面的部门、角色筛选及人员表单下拉加载。
- 状态：已确认。
- 影响：授予 `sys:depart:view` 和 `sys:role:paging`；不授予部门或角色的新增、编辑、删除及角色授权权限。

### D-025 员工端字典查询权限

- 日期：2026-09-03。
- 决策：员工端可读取通用数据字典，用于考试记录等页面的筛选下拉加载。
- 状态：已确认。
- 影响：向 `EMPLOYEE` 授予 `sys:dict:paging`；不授予字典新增、编辑或删除权限。

### D-022 头像菜单账号设置入口

- 日期：2026-09-03。
- 决策：管理员、HR 和员工在右上角头像下拉菜单中显示“账号设置”，进入本人资料修改页；候选人资料继续由 HR 管理，不开放自助编辑入口。
- 状态：已确认并实现。
- 影响：本人可以维护姓名、手机、邮箱、身份证号和头像；保存后前端立即接收并替换刷新后的登录会话。HR 同时获得资料修改与密码安全自助菜单权限。

### D-023 本地上传文件访问地址

- 日期：2026-09-03。
- 决策：本地上传插件返回 `/upload/file/...` 相对路径，前端按当前 API 域名解析，不再写死历史域名 `be2.yfhl.net`。
- 状态：已确认并通过 V011 Flyway 迁移实现。
- 影响：本地开发、局域网访问和同域部署均从实际保存文件的后端读取图片；移除头像时同步清空表单值。

### D-024 新账号默认头像

- 日期：2026-09-03。
- 决策：所有角色的新账号统一使用超级管理员当前头像作为默认头像。
- 状态：已确认并通过 V012 Flyway 迁移实现。
- 影响：管理员、HR、员工和候选人创建链路统一写入默认头像；历史空头像账号一并回填，已有自定义头像保持不变。

### D-026 账号权限与员工记录最小披露

- 日期：2026-09-03。
- 决策：员工端考试记录只展示考试名称和是否通过，不提供分数、试卷明细、标准答案或解析；HR 人员管理中的批量启停操作仅在具有 `sys:user:state` 时显示。
- 状态：已确认。
- 影响：员工端不再调用 `exam:record:list` 管理接口；`sys:user:batch-role` 补充为仅管理员持有的可授予权限。

### D-027 试题 Excel 导入规则

- 日期：2026-09-03。
- 决策：试题导入后默认启用；同一题库内相同题型和规范化题干视为重复并跳过，不覆盖旧题；统一模板支持单选题、多选题、判断题和简答题。
- 状态：已确认并通过 V015 及题目导入接口实现。
- 影响：导入采用先校验后确认的两阶段交互，正确行落库、错误行不落库，重复行和错误行均进入可下载的逐行报告。简答题本阶段只完成题库录入和存储，作答与人工阅卷仍按 Phase 4 后续实施。

## 2. 建议默认值

### R-001 考核码使用规则

- 建议：考核码绑定一个人和一条考核分配；首次使用后仍允许在未交卷、未过期时恢复；交卷或过期后失效。
- 理由：如果首次打开立即失效，刷新、断网或浏览器崩溃会让候选人无法恢复。

### R-002 多选题评分

- 建议：V1 采用完全匹配得满分，否则 0 分。
- 理由：与当前底座一致，规则简单且争议少。

### R-003 题目删除

- 建议：优先停用或逻辑删除，不物理删除已被试卷引用的数据。

### R-004 选项随机

- 建议：新考核模板默认开启，判断题不随机“正确/错误”的业务含义，但可保持固定显示顺序。
