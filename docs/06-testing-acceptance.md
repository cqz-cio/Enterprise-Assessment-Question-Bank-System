# 测试与验收工作文档

> 版本：V0.1  
> 用途：开发自测、联调、回归和业务验收

> 本地角色联调可在 Flyway 完成 `V001`～`V005` 后，按需导入
> `scripts/dev/import-role-test-accounts.sql`。该脚本不属于 Flyway 正式迁移，禁止用于生产；
> 候选人不使用账号密码，由 HR 在候选人考核页面发放姓名和 6 位口令后从 `/exam-entry` 验证。

## 1. 测试层次

- 单元测试：状态判断、考核码校验、评分计算、权限辅助方法。
- 服务集成测试：MySQL/Redis 条件下的创建分配、建卷、交卷和阅卷事务。
- API 测试：正常、无 token、过期、越权、重复提交和错误参数。
- 前端流程测试：管理员、HR、员工和候选人完整路径。
- 部署验收：新环境安装、局域网访问、备份恢复和端口限制。

## 2. 身份和权限用例

### AUTH-001 正式用户登录

- 前置：正常状态员工账号。
- 操作：账号密码登录。
- 预期：返回有效 token，只加载员工菜单。

### AUTH-002 待审核员工登录

- 前置：员工刚注册，状态为待审核。
- 预期：拒绝登录并给出待审核提示。

### AUTH-003 候选人考核码验证

- 前置：有效候选人分配及对应的 6 位考核码。
- 操作：输入正确姓名和考核码。
- 预期：返回候选人 token 和正确分配信息，不加载后台菜单。

### AUTH-004 防止凭证枚举

- 分别提交错误姓名、错误考核码和不存在数据。
- 预期：外部提示保持一致；后台安全日志可记录内部原因。

### AUTH-005 JWT 篡改

- 修改 token 中的用户名或过期时间。
- 预期：签名验证失败，无法访问接口。

### AUTH-006 横向越权

- 用户 A 使用用户 B 的 paperId 调用详情、答题、交卷和结果接口。
- 预期：全部拒绝，不返回试卷内容。

### AUTH-007 员工注册审核

- 员工可自由提交注册申请，注册后状态为待审核。
- 手机号和邮箱同时留空时仍可正常提交注册申请。
- 系统管理员或 HR 审核通过前，员工不能登录参加考试；通过后获得员工角色。

## 3. 候选人流程用例

### CAND-001 HR 发放考核

- HR 录入姓名、候选人编号、手机号、邮箱、岗位、批次、开始时间和截止时间。
- 系统自动匹配 `INTERVIEW` 模板并返回一次性展示的 6 位考核码。
- 未修改时间默认值时，截止时间等于开始时间加 14 天；HR 修改后以提交值为准。

### CAND-002 岗位无模板

- 岗位没有启用的 `INTERVIEW` 模板。
- 预期：禁止发放，提示管理员先配置模板；不得创建孤立用户和分配数据。

### CAND-003 中途恢复

- 候选人开始后答完部分题目，关闭浏览器，再次验证。
- 预期：返回同一 paperId，已保存答案仍存在，剩余时间正确。

### CAND-004 完成后重新进入

- 候选人已交卷。
- 预期：考核码不能创建新试卷；最终结果形成后仅能查看是否通过。

### CAND-005 考核过期

- 当前时间超过 expireAt。
- 预期：不能进入；进行中试卷按规则自动交卷或过期结算。

## 4. 随机组卷和快照用例

### PAPER-001 每人独立组卷

- 两名用户进入同一模板。
- 预期：生成不同 paperId，题目集合或顺序具备随机性。

### PAPER-002 题目不足

- 某题型启用题目数少于规则数量。
- 预期：创建试卷整体回滚，不留下空试卷或定时任务。

### PAPER-003 停用题不抽取

- 停用一批题目后重复创建测试试卷。
- 预期：新试卷不出现停用题；历史试卷不受影响。

### PAPER-004 历史快照

- 生成试卷后修改题干、选项、解析和正确答案。
- 预期：已生成试卷内容和评分依据不改变。

### PAPER-005 选项乱序判分

- 对同一单选/多选题生成不同选项顺序。
- 预期：显示顺序不同但正确答案映射和评分正确。

### PAPER-006 重复开始

- 同一分配并发调用两次开始接口。
- 预期：只生成一张试卷，另一次返回相同 paperId。

### PAPER-007 禁止重考

- 候选人或员工完成考核后，再次调用开始接口。
- 预期：返回已完成/禁止重考错误，数据库中不产生第二张试卷；如需再次考试，只能创建新的考核分配。

## 5. 作答和交卷用例

- 客观题保存后刷新页面，选中状态正确恢复。
- 简答题长文本、空文本和特殊字符可以正确保存。
- 已交卷试卷不能继续修改答案。
- 到时自动交卷与用户主动交卷同时发生时，只结算一次。
- 交卷失败后有明确错误，不错误标记为已完成。
- 前端不提前取得标准答案、正确性或解析。
- 交卷响应不包含客观分和最终分；最终完成前只显示“结果待生成”。

## 6. 评分和阅卷用例

- 单选题正确得满分，错误得 0 分。
- 多选题完全匹配得满分，少选、多选、错选默认得 0 分。
- 判断题正确映射得分。
- 含简答题的试卷交卷后为 `PENDING_REVIEW`。
- 简答题评分不能小于 0 或超过满分。
- 尚有未评分简答题时不能 finalize。
- finalize 后总分、是否通过、assignment 和 exam_record 同步更新。
- finalize 成功后无需 HR 操作，考生立即可以查询是否通过。
- 修改已经评分的题目时产生 grading log。
- 最终完成后，候选人和员工结果接口只返回是否通过，不返回客观分、主观分、总分、答案或解析。

## 7. Excel 用例

- 正确模板可以完整导入，导入题目默认启用。
- 缺少必填列时整批拒绝并说明缺失列。
- 题型或难度不存在时给出具体行号。
- 多选正确答案格式错误时拒绝该行。
- 文件结构有效但部分数据行错误时，正确行正常导入，错误行不落库并生成逐行错误报告。
- 候选人模板中的姓名、候选人编号、手机号、邮箱、岗位编码、批次、开始时间和截止时间均按必填字段校验。
- 同一题库中相同题型和规范化题干视为重复，跳过且不覆盖已有题目；文件内部重复也采用相同规则。
- 单选、多选、判断、简答四种题型均可导入；简答题不生成选项，参考答案和评分要点正确保存。
- 公式单元格、超长文本、空行和合并单元格不会导致服务异常。
- 成绩导出的数据与筛选条件、权限范围一致。

## 8. 性能和稳定性验收

- 100 名用户在短时间内开始考试，建卷无重复、无明显锁等待。
- 100 名用户每 5 到 10 秒保存一次答案，接口保持可用。
- MySQL 或 Redis 暂时不可用时返回明确错误，恢复后能够继续服务。
- Quartz 自动交卷任务重复触发时结果保持幂等。
- 日志目录有轮转策略，不会无限增长占满磁盘。

## 9. 部署验收

- 公司局域网内授权终端可以访问应用。
- 未授权公网不能直接访问应用、MySQL 或 Redis。
- 数据库和 Redis 数据卷重启后保留。
- 能够完成一次数据库备份和恢复演练。
- 生产配置中不存在源码硬编码密码和 JWT 密钥。
- Swagger 在生产关闭或仅对管理网络开放。

## 2026-09-24 实际全链路回归入口

新增 `scripts/qa/`，在独立 MySQL 库、Redis 和后端上运行真实接口与浏览器场景，覆盖注册审批、三场景模板、发放、恢复、幂等、自动/人工评分、导入导出、越权、过期与并发。执行命令、具体断言和清理规则见 [测试说明](../scripts/qa/README.md)，本次实测结果及限制见 [验收报告](./DAILY_USE_ACCEPTANCE_2026-09-24.md)。场景代码以 D-010/D-033 为准。

### D-039 修复的必测项

- 清单关闭、页面刷新、真实服务进程重启后恢复原 taskId 和全部原码；同文件重传/重复提交不新增分配。
- 未登录、普通员工、其他 HR、权限撤销、到期任务不能读取清单，响应为 no-store。
- 归档不含明文，错误密钥/密文篡改/替换所有者拒绝解密；码重置、停用或过期后恢复/导出不暴露旧码。
- 归档写入失败回滚同一行发放；部分成功中断后只恢复处理剩余行；跨服务实例并发不重复创建。
- 密码修改后明确提示成功、退出旧会话，新密码能够重新登录。
- 全量前端类型检查通过并作为 CI 阻断项；本轮完整回归使用 `--skip-load`，容量与备份按用户要求暂缓。
